Critical

Critical P1: Stale BodyID in SyncJoltToECS
JoltBackend.cpp:562, 567-572

BodyID reconstructed from index only (JPH::BodyID(bodyIndex)) — loses generation ID. Subsequent GetPosition(), GetLinearVelocity() dereference potentially freed bodies. Risk: use-after-free, data corruption.

Fix: Store full BodyID or use BodyLockRead pattern to validate before access.

Critical P2: Stale BodyID in DestroyBodyForEntity
JoltBackend.cpp:515, 521-522

Same BodyID reconstruction issue. RemoveBody()/DestroyBody() may operate on a different entity's body if the slot was reused.

Fix: Store full BodyID instead of just the index.

Critical P3: Box2D Contact Event Tracking Logic Error
Box2DBackend.cpp:410

newContacts.erase(pairKey) in END event loop corrupts the active contact set. newContacts is built from BEGIN events only — erasing from it during END processing causes collision exit callbacks to be lost.

Fix: Remove the newContacts.erase() call at line 410.

Critical P4: Missing Mass Validation in Gravity Zones
JoltBackend.cpp:660

Force = customGravity * gravityScale * mass. If mass ≤ 0 or NaN, force becomes invalid causing extreme physics instability.

Fix: Guard: if (rb->mass > 0.0001f) before force application.

Critical

Critical S1: Path Traversal via Symlinks in #include
ScriptEngine.cpp:1091-1104

isPathSafe() uses lexically_relative() which operates on strings only and doesn't resolve symlinks. An attacker can create a symlink in the scripts directory pointing outside it, bypassing the restriction.

Fix: Use std::filesystem::canonical() to resolve symlinks before checking path containment.

Critical S2: Unbounded Event Listener Registration
ScriptEvents.cpp:27

Scripts can register unlimited listeners per event via Events_Listen(). Each holds an AddRef() on the callback, allowing memory exhaustion.

Fix: Cap at 1,000 listeners per event or 10,000 total.

Critical S3: Unbounded Entity Creation via Bindings
ScriptBindings_Scene.cpp:158-194

Scene_Instantiate() / Scene_InstantiateAt() create entities in native code — not counted against the 1M instruction limit. A script loop can exhaust memory.

Fix: Per-frame entity creation cap (e.g., 1,000).

Critical S4: Unbounded Prefab Instantiation
ScriptBindings_Prefab.cpp:20-41

Same issue as S3 but amplified — each prefab can contain many entities/components, rapidly exhausting memory.

Fix: Share per-frame entity creation cap with S3.

Critical

Critical R1: WaterVolumeComponent Crash on Missing Fields
SceneSerializer.cpp:508-527

Deserialization accesses j["halfExtents"], j["waterColor"], j["opacity"], j["waveSpeed"], j["waveHeight"], j["priority"] WITHOUT .contains() checks. Throws std::out_of_range on old/malformed scene files.

Fix: Wrap all field accesses with .contains() checks matching the pattern used in other deserializers.

Critical R2: HealthComponent Missing Runtime State
SceneSerializer.cpp:1780-1806

currentHealth, currentShield, isDead, invulnerabilityTimer, timeSinceLastDamage are NOT serialized. All health/damage state is lost on save/load — only config values (maxHealth, regen rates) survive.

Fix: Add all runtime state fields to both serialize and deserialize helpers.

Critical R3: RigidbodyComponent Missing Velocity State
SceneSerializer.cpp:1472-1506

velocity, angularVelocity, maxVelocity, maxAngularVelocity, isGrounded, isSleeping are NOT serialized. Moving objects freeze in place on load.

Fix: Add velocity and state fields to serialization.
