1Architecture

Enjin is a from-scratch C++20 engine in four strict layers. Each layer only depends downward; the renderer, physics, and platform are behind interfaces so backends swap without touching gameplay code.

Play mode enter / exit

Play serializes the editing scene to an in-memory snapshot, creates physics backends per project mode, wires script-engine subsystem pointers, boots gameplay/audio/accessibility systems, and dispatches OnCreate. The in-loop order matters: physics steps first, 3D collision events dispatch to scripts, a second 2D sync prevents one-frame-late sensor events, then the ~20 gameplay systems tick. Stop tears backends down, restores the snapshot, and PlayModeDiff offers changed entities as a cherry-pick apply dialog.

Script lifecycle

.as file → sandboxed compile (canonical-path include containment, depth 16, 1M instruction cap) → OnCreate at play start → OnUpdate/FixedUpdate/LateUpdate per frame → coroutines resumed by the scheduler (yield seconds/frames/end-of-frame) → OnDestroy. Hot reload recompiles on file change; script-initiated destroys are deferred and flushed after the script pass.

Reading the numbers. The editor-only findings (VWS snapshot) cost nothing in a shipped game. The engine-wide ones — the World mutex, per-frame draw-list allocation and sort, and the physics sync patterns — are what stand between the current engine and the 120-FPS-no-matter-what pillar on low-end hardware. The mutex is the deepest cut: it is architectural, and fixing it (storage-level iteration instead of per-entity locked lookups) also fixes findings 3.2's lock-churn rows for free.

4Lazy Spots

Places where the code takes a shortcut a user eventually notices: stubs behind real APIs, hardcoded tunables, silently dropped features, settings nothing reads.

Resolved 2026-07-17 — the trio, honestly

Three headline systems — Volumetric Fog, Software DDGI, and the GPU Particle System — were scaffolded in one pass and all stopped at the same line: the per-frame parameter UBO was never uploaded, so every Settings slider was dead. Closing them showed they were not one bug — only fog had its consumer end wired:

  • Volumetric fog — DONE, validation-clean while running. The UBO was one of five missing pieces (light SSBOs, image lifecycle, real prev-frame VP, the apply-path binding). Fixed end to end; the froxel path now runs with zero validation errors. Off by default; runtime toggle works. (See commit history.)
  • Software DDGI — ACTIVATED (2026-07-18). Now end to end: the voxelizer is fed the merged static geometry (a MeshInstance SSBO of pool-eligible meshes), probes trace the resulting SDF, and the PBR fragment shader samples the probe irradiance atlas directly via world position + normal — no screen-space pass, no G-buffer (the chosen design). The stride bug (24 vs 34 float vertex) and an atlas-width miscompute that would have scrambled every probe were caught and fixed. Enable via Rendering > Software DDGI on a lit 3D scene; needs static geometry present. Remaining polish: probe visibility (Chebyshev) term, transform-refresh on moving meshes, intensity slider.
  • GPU particles — simulation correct, self-gated. The emitter UBO uploads properly now, but nothing calls Spawn() and Render() has no draw path. It no longer burns a 65,536-wide dispatch every frame on every scene — it stays dormant until something spawns. Finishing = an ECS emitter spawn source + a billboard render pipeline. The CPU particle path works today.

Lesson banked: a Settings slider should ship in the same commit as the code that consumes it.

5PC (Vulkan) vs Web (WebGPU) Parity

Feature-by-feature matrix. "N/A" means intentionally out of scope for the web target.

Top gaps by user impact

  1. No UI, HUD, or menus on web — UISystem/HUDSystem/GameMenuSystem never initialize in web_main.cpp. Any game with UI looks broken.
  2. No text rendering — TextComponent has zero references in the web render half.
  3. Sprites are untextured — web draws tinted white quads, rotation hardcoded to 0. 2D games are effectively broken on web.
  4. AI and Dialogue never tick — AISystem, DialogueSystem, StateMachineSystem absent from the web loop; NPCs freeze.
  5. Saves don't persist — web writes land in Emscripten MEMFS and vanish on page reload; no IDBFS/localStorage bridge, no autosave update.
  6. Water, terrain, scene skyboxes, weather rendering, elemental effects are all invisible on web (WeatherSystem even updates — nothing renders it).
  7. Accessibility runtime absent — subtitles, announcer, alternative input, content warnings all desktop-only; web keeps only the colorblind/brightness/contrast shader. This conflicts with the Accessibility-Everything pillar.

How to read this. The web renderer's PBR core is honest parity — same math, same analytic fog, working shadows for one sun + a few lights. What the web build actually lacks splits into two families: engine systems that simply never tick in web_main.cpp (UI, text, AI, dialogue, accessibility, save persistence — these are wiring work, not renderer work), and renderer features excluded from the WASM build (water, terrain, skybox assets, GI, post-fx depth — these are real porting work). The first family is the cheap, high-impact half: most of it is instantiating existing cross-platform systems in the web boot path.
