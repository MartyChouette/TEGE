## Physics Findings

### PHYS-C1 — Collision pair key exit event ordering [ACCEPTED]
- **File:** JoltBackend.cpp:1042-1043, Box2DBackend.cpp:304-308
- **Issue:** MakeCollisionPairKey stores min(a,b)/max(a,b), so exit events report entities in canonical order rather than source order.
- **Resolution:** Added documentation comment. Entity IDs are correctly identified; only ordering differs. Consumers should not rely on A/B ordering. Not a functional bug.

### PHYS-H1 — Zero-length raycast direction [FIXED]
- **File:** Box2DBackend.cpp:503, 548
- **Issue:** Normalized() on zero-length direction produces NaN.
- **Fix:** Added length check before normalization; early return if < 0.0001f.

### PHYS-H2 — Zero-length prismatic joint axis [FIXED]
- **File:** Box2DBackend.cpp:712
- **Issue:** Normalized() on zero-length axis crashes or produces degenerate constraint.
- **Fix:** Added length check; defaults to X axis if zero-length.

### PHYS-H3 — Unguarded hinge joint limits [FIXED]
- **File:** JoltBackend.cpp:869-871
- **Issue:** If lowerLimit > upperLimit, Jolt creates unstable constraint.
- **Fix:** Added min/max normalization before setting limits.

### PHYS-H5 — Duplicate body leak on CreateBodyForEntity [FIXED]
- **File:** JoltBackend.cpp:394, Box2DBackend.cpp:187
- **Issue:** Calling CreateBodyForEntity twice for same entity leaks the old body handle.
- **Fix:** Added duplicate check + DestroyBodyForEntity + warning log in both backends.

### PHYS-M1 — Entity ID truncation in pair key [ACCEPTED in PHYS-C1]
- Already documented in header with WARNING comment. Entity IDs are u64 but pair key uses 32 bits per entity. Acceptable for current entity ID ranges.

### PHYS-M3 — Silent polygon fallback [FIXED]
- **File:** Box2DBackend.cpp:267-269
- **Issue:** Invalid polygon (< 3 or > 8 vertices) silently falls back to unit box.
- **Fix:** Added ENJIN_LOG_WARN before fallback.

## Audio Findings

### AUD-C1/H2 — Material indices bounds mismatch [FIXED]
- **File:** SteamAudioProcessor.cpp:142
- **Issue:** No validation that materialIndices.size() == numTriangles. Mismatched arrays cause out-of-bounds reads in Steam Audio SDK.
- **Fix:** Added size validation after indices divisibility check; returns false with error log.

### AUD-C3 — Missing null check on inMono in Process [FIXED]
- **File:** SteamAudioProcessor.cpp:369
- **Issue:** Audio callback may pass nullptr during initialization/shutdown/underrun.
- **Fix:** Added null check for inMono, outStereo, and frameCount == 0 at function entry.

### AUD-C2 — Early return cleanup [NOT A BUG]
- **File:** SteamAudioProcessor.cpp:282
- Audit flagged early return after failed binaural effect creation as leaking buffers. However, buffers are allocated *after* this point (line 314), and the effect wasn't created (failure path), so there is nothing to clean up.

### AUD-H1 — Buffer overflow in stereo interleave [NOT A BUG]
- Buffer sizes are controlled by miniaudio node configuration and m_FrameSize. The count is clamped to m_FrameSize, and outStereo is allocated as m_FrameSize * 2. Safe in practice.

## Build Pipeline Findings

### BLD-H1 — Missing path traversal on non-material assets [FIXED]
- **File:** BuildPipeline.cpp:264-352
- **Issue:** Path traversal check only applied to material textures, not sprite2D, audio, script, tilemap, tree, or shrub paths.
- **Fix:** Extracted `validateAssetPath` lambda with traversal guard, applied to all 7 asset types.

### BLD-H2 — Unchecked decompression result [FIXED]
- **File:** AssetReader.cpp:280
- **Issue:** DecompressData returns empty on failure, but caller doesn't check before CRC (would fail with confusing "CRC mismatch" message).
- **Fix:** Added explicit empty check after DecompressData with distinct error message.

### BLD-H3 — Missing gcount check in AddFile [FIXED]
- **File:** AssetPacker.cpp:91
- **Issue:** File read not verified for completeness before passing to AddData.
- **Fix:** Added gcount check + error log + early return on incomplete read.

### BLD-H4 — Integer overflow in size accumulation [ACCEPTED]
- **File:** AssetPacker.cpp:145-146
- Existing MAX_SINGLE_FILE (1 GB) and MAX_ENTRIES (100K) caps make u64 overflow impossible (max total ~100 TB). No change needed.

### BLD-M1 — Missing BuildConfig dimension validation [FIXED]
- **File:** BuildPipeline.cpp:15
- **Issue:** windowWidth/windowHeight never validated. Zero or extreme values passed through.
- **Fix:** Added bounds check (1-7680 x 1-4320) at start of Execute().

### BLD-M2 — Path traversal in AppImageBuilder extraFiles [FIXED]
- **File:** AppImageBuilder.cpp:294
- **Issue:** extraFiles paths not validated, could reference arbitrary system files.
- **Fix:** Added `..` check on lexically_normal path, skip with warning.

### BLD-M3 — Missing HTML escaping in splash extension [FIXED]
- **File:** HTML5Exporter.cpp:165
- **Issue:** File extension inserted into HTML src attribute without escaping.
- **Fix:** Wrapped with HtmlEscape().

### BLD-M4 — Non-unique/unsafe div ID in embed codes [FIXED]
- **File:** NewgroundsGamePage.cpp:1387
- **Issue:** EscapeHTML(title) used as HTML id attribute — contains spaces and entities, not valid.
- **Fix:** Added sanitization that strips non-alphanumeric chars, converts spaces to hyphens.

### BLD-M5 — Unbounded asset collections [ACCEPTED in BLD-H4]
- Already bounded by MAX_ENTRIES (100K) in AssetPacker. BuildPipeline collections mirror what's packed. Acceptable.
